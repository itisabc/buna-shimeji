しめじ Action コマンド一覧

Shimeji-Desktop（DalekCraft2 版）から Rust へ再実装するアクションの全種類と、それぞれの「マスコットの動き」。
参照: Java 実装 .tmp/java-ref/action/（38 クラス）・設計 .tmp/design.md §1.8（2026-09-06 確定）

15 種
資産で使用 → フル実装（Java 逐語移植・期待値焼き込みテスト）
資産 actions.xml が実際に参照する 10 クラス + Type 系 5 種
17 種
資産外 → stub（置き物）（呼ばれても即完了・警告ログ）
うち 5 種は Java でも @Deprecated（実質別アクションと同一）
「40 種」の数え方について: Java 実装は 38 クラス （= アクション種別 32 種（資産内 15 + 資産外 17）+ 基底・共通クラス 5 + 例外 1）。 設計書の「Action 40 種」はこのアクション種別群を指す呼称です。
stub とは: Java 版は資産 XML が参照したクラスだけを動的に読み込むため、 資産で使わないクラスは実行時には一切動作しません（= この資産では実質「死にコード」）。 Rust 版では全種類を enum で定義する必要があるため、資産外は「即完了する置き物」にします。 万一将来の資産セットが stub を参照したら起動時にエラー（fail-fast）で検出できます。

基盤クラス（共通の仕組み・5 + 1）

クラス役割
Action
インターフェース
 全アクションの契約: init（開始）/ hasNext（継続判定）/ next（1 tick 実行）/ isDraggable（掴めるか）
ActionBase
共通基底
 ほぼ全アクションの土台。相対時刻（時間 = マスコット時刻 − 開始時刻）、アニメ選択（条件一致の最初の 1 枚）、affordances（他マスコットへの合図）・hotspots（クリック判定域）の更新、共通属性の既定値
属性: Duration（上限。既定=無限）/ Condition（既定=true）/ Draggable（既定=true）/ Affordance（既定="")
BorderedAction
基底
 「床・壁・天井に沿った動き」の土台。BorderType 属性で境界を取得し、毎 tick そこに沿ってアンカーを再配置。Rust 版は BorderRef トークン方式（#7a）で移植
InstantAction
基底
 1 tick で終わる単発アクションの土台（hasNext=常に false）。Look / Offset / Mute の親
ComplexAction
基底
 子アクション列を先頭から順に実行する土台（現在の子が終わったら次へ進む = seek）。Sequence の親
LostGroundException
例外
 アクション継続不可能（地面/境界を失った、窓が消えた等）。捕まえると BehaviorRunner が「Fall（落下）」へ切り替える

A. 資産で使用 — フル実装 15 種（#7b で Java 逐語移植）

A-1. Type 系（actions.xml の Type 属性で直接使う・5 種）

アクション予想される動き詳細・主な属性資産での使用例
Stay
BorderedAction 継承
Type資産内		 その場でじっとアニメ再生。座る・佇む・眠るなど 境界属性がある場合はそこから外れた瞬間に LostGround → 落下へ切り替え。アニメは Condition 条件一致の最初の 1 枚を使う Sit / Sleep / FallOnKnee 等 10 定義
Move
BorderedAction 継承
Type資産内		 目標座標へ歩く。歩きアニメを循環再生 TargetX/TargetY（既定=制限なし）へ向かって移動。ポーズ自身の Velocity で実際に動く。目標の方向へ自動で向き直り（向きが変わる瞬間は IsTurn アニメを再生）。到達時に飛び越えていたら目標へクランプ（overshoot 補正）。境界から外れたら LostGround Walk / RunWithIE 等の土台
Animate
BorderedAction 継承
Type資産内		 アニメを 1 回通しで再生（境界に沿って） Stay とほぼ同型だが「Duration で区切ったアニメ再生」が主目的。境界から外れたら LostGround Parachute / SitOnIe 等の土台・5 定義
Sequence
ComplexAction 継承
Type資産内		 複数の動きを順番に連続実行 子（Reference で他アクション参照 / Inline で直接定義）を先頭から順に。全部終わったら次の行動へ。Loop="true" なら最後まで行ったら先頭へ戻る（資産 55 箇所で使用・Dragged は true）。子参照に渡した属性（例: Condition）は参照先へ引き継がれ、確率分岐（Tripping の 5% 転倒）が成立する StandUp / Fall / WalkAlongWorkAreaFloor 等 59 定義（最多）
Select
Sequence 同一
Type資産内		 Sequence と同じ（別名） Java 実装は空クラス（Sequence をそのまま継承）。読みやすさのための別名 Inline ネストで 3 使用

A-2. Embedded クラス（actions.xml が Class= で参照・10 種）

クラス予想される動き詳細・主な属性資産での使用例
Look
InstantAction 継承
Embedded資産内		 その場で振り向く（1 tick） LookRight 属性（true=右を向く / 既定=反対方向）。アニメなし Turn 行動（ランダム振り向き）
Offset
InstantAction 継承
Embedded資産内		 その場のまま位置をずらす（1 tick） X/Y を生値（スケール不変）でアンカーへ加算。壁登りと組み合わせる「細かい位置調整」専用（スケールをかけると資産の座標系が崩れるため意図的に生値） ClimbWall 等の段差調整
Jump
ActionBase 継承
Embedded資産内		 目標へ放物線でジャンプ（窓から飛び降り等） TargetX/TargetY/VelocityParam（既定 20.0）。目標へ向かう放物線速度を毎 tick 計算し VelocityX/VelocityY 変数としてアニメに注入。目標距離が速度以下になったら目標座標へスナップ JumpFromLeftWall / JumpFromIE 等
Fall
ActionBase 継承
Embedded資産内		 重力で落下する（全ての「落ちる」の芯） InitialVx/InitialVy/Gravity/ResistanceX/ResistanceY。毎 tick 重力加速+空気抵抗減衰。1 tick 分の移動を dev 分割して小刻み衝突判定（床から弾かれても最大 80px 上方向で床を再探索・下向き時のみ）。床/壁に着いたら停止。VelocityX/VelocityY 変数注入。Rust 版は Java の half-up 四捨五入（java_round）を必須に再現 Fall（必須ビヘイビア）/ FallFromWall 等
Dragged
ActionBase 継承
Embedded資産内		 マウスで引きずられている状態（必須ビヘイビア） カーソル位置+OffsetX/OffsetY（既定 0/120・OffsetType="Origin" なら画像中心基準）へ追従。足元ぶりの揺れを物理っぽく減衰（0.1/0.8 係数・FootX/FootDX 変数注入 → アニメ条件で足元アニメ切替）。カーソルを離すと BehaviorRunner が「Thrown」へ。250tick 毎に 10% で自発的に手を放す（rng 消費は条件成立時のみ・短絡一致）。refreshWorkArea 呼び出しは Rust 版で no-op 化+コメント保持（design §1.7(e)-3） Dragged（必須ビヘイビア・Loop="true"）
Regist
ActionBase 継承
Embedded資産内		 窓の端っこに「ヒョイッ」と座る（窓端座りの着地演出） アニメ再生中はドラッグ状態。終了フレームで 50% の確率で振り向き（rng）した後 LostGround → 落下へ。OffsetX/OffsetType は Dragged 同型 SitOnTheLeftEdgeOfIE 等の末尾
WalkWithIE
Move 継承
Embedded資産内		 インタラクティブウィンドウ（IE 窓）を担いで歩く IeOffsetX/IeOffsetY（生値・マスコットが窓のどこを掴むか）。歩きながら窓も同じ量だけ動かす（moveActiveIE）。窓が見えない/掴み位置がずれたら LostGround。throwing_allowed トゲート有効時のみ動く。RunWithIe は BorderType=Floor 版 WalkWithIe / RunWithIe
ThrowIE
Animate 継承
Embedded資産内		 窓を「ブンッ」と投げ飛ばす InitialVX=32 / InitialVY=−10 / Gravity=0.5（スケール適用）。毎 tick 窓を初速+重力で移動。開始時に掴んでいた窓の ID を記憶し、途中で別窓に切り替わったら中断。throwing トゲート有効時のみ ThrowIEFromLeft / RunAndThrowIEFromRight 等
FallWithIE
Fall 継承
Embedded資産内		 窓を担いだまま落下する Fall の落下物理+WalkWithIE の掴み維持（ずれたら LostGround）を合成。着地後も窓を運ぶ。throwing トゲート有効時のみ FallWithIe
Breed
Animate 継承
Embedded資産内		 アニメ（分裂動作）の最後の 1 フレームで子マスコットを湧かす BornX/BornY（生まれる位置のオフセット・向きで左右反転）/ BornBehaviour（子の初期行動）/ BornMascot（子の画像セット・既定=自分と同じ）/ BornTransient（使い捨て子フラグ）/ BornInterval / BornCount。「増殖」トグル・「Transients」トゲートの両方で制御（#7b は EnvironmentView 経由で供給）。Rust 版はスポーンをキューイングし次 tick で一括反映（AGENTS.md §5-6 踏襲・Java 即時との意図的差異） PullUpShimeji1 / Divide1（増殖行動）

B. 資産外 — stub 17 種（呼ばれても即完了・将来実装可能な形で置く）

Java 版も資産 XML が参照しないクラスはロードされず実行されないため、 実行系としての挙動は「stub（即完了+警告ログ）」と一致します。 下表は将来実装したときの動きの説明。Embedded FQN が未知だった場合は stub ではなく起動エラー（fail-fast）。

B-1. @Deprecated（Java 1.0.21 で統合済み・実質 Animate/Move/Stay/Jump と同一・5 種）

クラス実質説明
BroadcastDeprecated= Animate1.0.21 でブロードキャスト機能が ActionBase 本体へ統合され、これら 4 クラスは親クラスと完全に同一の動作になりました（Java ソースは継承宣言のみ）。資産でも使われていないため stub。将来の資産互換のため名前だけ残る
BroadcastJumpDeprecated= Jump
BroadcastMoveDeprecated= Move
BroadcastStayDeprecated= Stay
MoveWithTurnDeprecated= Move + 向き直り強制Move と同じだが向き直りアニメ（最後のアニメ）を強制使用。1.0.21 で Move 本体へ turning 機能が統合され deprecated。stub

B-2. 実装保留（Phase 2・12 種）

クラス将来実装したときの動き詳細（Java 実装の内容）
Turnstub その場で向きだけを変える BorderedAction。現在の向きと action の向きが違う間、振り向きアニメを再生して完了したら終了
Transformstub 別の画像セット（キャラ）へ変身する Animate 継承。アニメ最終フレームで TransformMascot セットへ画像差し替え+TransformBehaviour 行動へ切り替え。「変身」トグル（transformation）が有効時のみ。AGENTS.md の R9（差し替え容易）と直結する将来実装候補
SelfDestructstub アニメを演じた後自分自身を消す Animate 継承。最終フレームで dispose（マスコット削除）。使い捨てマスコットの退出演出用
Mutestub 効果音を止める（1 tick） InstantAction 継承。Sound 属性指定ならその音だけ、無指定なら全効果音停止。効果音実体は Phase 1 外（効果音枠のみ実装）のため先行実装は不要
BreedMovestub 歩きながら定期的に増殖する Move 継承+Breed の増殖ロジック。BornInterval 毎のフレームで増殖
BreedJumpstub ジャンプしながら定期的に増殖する Jump 継承+Breed の増殖ロジック。同上
ComplexMovestub 目標へ歩き、到着したら自分と相手の行動を両方切り替える。増殖・対象スキャンにも対応 BorderedAction 継承。Characteristics（Breed/Scan）、Behaviour/TargetBehaviour、TargetLook。Move の移動+到着時の双方向 Behavior 変更+Breed 増殖+Scan（affordance 持ちマスコット探索）。Manager 連携（他マスコット検索・Behavior 変更）が必要なため Phase 2 で EnvironmentView 拡張込みで実装
ComplexJumpstub 目標へジャンプし、到着したら自分と相手の行動を両方切り替える ActionBase 継承（Jump 相当の移動+Breed/Scan 特性）。到着時の双方向 Behavior 変更+TargetLook（向かい合わせ）。Phase 2 対象
ScanMovestub 合図（affordance）を出している相手を探して歩き、接触したら両者の行動を切り替える BorderedAction 継承。ターゲット追尾+向き直りアニメ+overshoot クランプ+到着時の双方向 Behavior 変更。Manager の getMascotWithAffordance が必要。Phase 2 対象
ScanJumpstub 合図を出している相手へジャンプし、着地したら両者の行動を切り替える ActionBase 継承。ScanMove のジャンプ版。Phase 2 対象
ScanInteractstub 合図を出している相手のそばで干渉アニメを演じ、終わったら両者の行動を切り替える BorderedAction 継承。ターゲット追尾+向き直りアニメ+干渉アニメ末尾で双方向 Behavior 変更。Phase 2 対象
Interactstub 他のマスコットと重なっている間だけ干渉アニメを演じ、終わったら行動を切り替える Animate 継承。hasOverlappingMascotsAtPoint（自分の位置に重なりがあるか）を hasNext 条件に使用。Phase 2 対象

共通用語の凡例

  • LostGround: アクション継続不可能（地面を失った・窓が消えた・掴みが外れた）→ BehaviorRunner が捕まえて「Fall（落下）」へ切り替え。マスコットが空中に残らないための安全網
  • アニメ選択: 複数アニメから「Condition 式が true になった最初の 1 枚」を毎フレーム選び直す（#{...} 式は毎フレーム再評価）
  • 変数注入: アクションが VelocityX/FootX 等をアニメ式へ渡す。アニメの条件式から参照できる（例: #{FootX < mascot.environment.cursor.x-50}）
  • スケール不変（生値）属性: Offset の X/Y、WalkWithIE/ThrowIE 系の掴みオフセットはスケールを適用しない（資産の座標系が崩れるため。Java の意図的仕様）
  • rng 消費点: Dragged（10% 自発離手・短絡評価）と Regist（終了時 50% 振り向き）のみ。Rust 版は乱数注入式（テスト可能）で Java の Math.random と同じ 2 点だけを消費
