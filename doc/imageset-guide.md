# 画像セット差し替えガイド

## 1. 概要

新しいマスコット画像セットは、**`img/` 配下に「セット名のフォルダ + 透過 PNG」を置くだけで**利用できます（XML やコードの追加は不要）。

対象読者: Java 版 Shimeji-ee の画像資産をそのまま流用したい人 / 生成 AI で作った画像を差し込みたい人。

本ガイドの記述はすべて実装（`src/`）と同梱資産（`conf/` `img/`）の実物確認に基づきます。画像の参照は全セット共通の 1 つの `conf/actions.xml` が担うため、新セットには XML・コードの追加が不要です。ただし `actions.xml` が参照する画像名は各セットで揃える必要があります（欠落時の扱いは §6）。Action 定義（コマンド一覧）の参照は `doc/action-catalog.html` を、ビルド・実行方法は README を参照してください。

## 2. ディレクトリ構造

```text
<shimeji.exe と同じ場所>/
├─ conf/                  全セット共通（セット固有の定義は conf/<Set>/ にも置ける）
│   ├─ actions.xml        アクション定義（画像の参照はここ）
│   ├─ behaviors.xml      行動と頻度
│   ├─ Mascot.xsd         XML スキーマ（実行時には参照されない・ドキュメント用）
│   ├─ settings.toml      トグル操作時に自動生成（無くても動く・§5）
│   ├─ lang/              言語辞書（en.toml / ja.toml・§10）
│   └─ <Set>/             セット固有の actions.xml / behaviors.xml（任意）
├─ sound/                 効果音の共通置き場（任意・§11）
└─ img/
    ├─ KuroShimeji/       1 フォルダ = 1 画像セット（フォルダ名 = セット名）
    │   ├─ shime1.png … shime46.png
    │   ├─ conf/          セット固有の定義（任意・最優先）
    │   ├─ sound/         セット固有の効果音（任意・§11）
    │   └─ banner.bmp     （.png 以外のファイルは読み飛ばされる）
    └─ Shimeji/           同構成
```

- `conf/` と `img/` は **exe と同じ場所**にある必要があります（起動実行ファイルの親ディレクトリ基準）。無い場合は欠落パス入りのエラーを表示して起動終了します。`cargo run` で起動した場合は exe が `target/release/`（debug は `target/debug/`）に生成されるため、その場所に `conf/` `img/` が必要です。
- 画像セットは `img/` 直下の **ディレクトリのみ** が対象です。フォルダの中にフォルダを入れても読まれません。
- セットの列挙は **辞書順**（文字列のソート順。英字は大文字が小文字より先、例: `"Zoo" < "apple"`）です。この順序が次の意味を持ちます:
  - 先頭（辞書順最小）のセットが **既定セット** になります。既定セットは「欠落参照アニメの無効化」と「構築時 scale（§5・§8）」の対象であり、Reload 時に消滅したセットのマスコットの付け替え先にもなります。同梱資産では `KuroShimeji` が既定セットです。
  - トレイ「呼ぶ」サブメニュー（トレイ・マスコット右クリック共通）の並び順と、「（ランダム）」spawn の選択元の順序も同じ列挙順です。
- `actions.xml` / `behaviors.xml` は既定では **`conf/` 直下の 1 つ** が全セット共通で使われます。セット固有に変えたい場合は `img/<Set>/conf/` または `conf/<Set>/` に同じファイル名で置くと、そのセットだけ別定義を使えます（探索順は `img/<Set>/conf/` → `conf/<Set>/` → `conf/`。ファイル名の候補は Java 版準拠で `actions.xml` / `動作.xml` / `one.xml` / `1.xml`、`behaviors.xml` / `behavior.xml` / `行動.xml` / `two.xml` / `2.xml`）。

## 3. PNG 命名規則

- `actions.xml` の各 `<Pose>` の `Image` 属性が、`img/<セット名>/` 直下の PNG ファイル名に対応します。先頭の `/` は読み込み時に自動で除去されるため（資産の記法 `Image="/shime1.png"` → `shime1.png`）、`/` 付きでも無しでも同じです。
- ファイル名の一致は **大小区別あり** の文字列比較です（`Shime1.PNG` は `shime1.png` と一致しません）。
- 対象はセット直下の拡張子 `.png` のファイルのみです（拡張子判定は大小を問わない）。サブフォルダ内の PNG や `.bmp` 等は読み飛ばされます（資産の `banner.bmp` は読まれません）。
- **画像サイズは PNG から動的に読むため、128px 固定ではありません。** 高解像度画像への差し替えが可能です。ただしアンカーは画像サイズに自動追従しないため、次のいずれかで整合させてください:
  - `settings.toml` の scale で元の寸法へ戻す（例: 2 倍解像度（256×256）の画像 + `scale = 0.5` → 128×128 として扱われ、アンカーも 0.5 倍に自動変換される。既定セット制限の例外は §5 参照）。
  - `actions.xml` 側の `ImageAnchor` / `Velocity` を新寸法に合わせる（XML は全セット共通のため、他セットにも影響します）。
- 同一セット内でサイズが混在しても警告 1 件で続行し、各フレームは自身の寸法のまま描画されます。
- **透過 PNG 必須です。** α=0（完全透明）のピクセルは OS レベルでマウス透過になります（その領域はクリックできず、下のウィンドウが反応します）。画像の外形マスクを兼ねるため、背景は必ず透明にしてください。透過なしの PNG は背景色の四角として表示され、矩形全体がクリック対象になります。
- 対応形式は PNG のみです（JPEG 等は読めません）。

## 4. アンカー dx/dy

- `<Pose>` の `ImageAnchor="x,y"` は、**画像左上原点からアンカー点（マスコットの足元基準点）へのオフセット** です。描画時は「ウィンドウ左上 = アンカー座標 − (x, y)」で配置されます。
- 同梱資産の標準は `ImageAnchor="64,128"`（128×128 画像の底中央。y=128 は最下行の下端線上）です。座り等の別ポーズでは 48 / 104 / 112 等が使われています。
- **左右の向きは 1 枚の画像から表現されます。** 素の画像は「左向き」基準で、右向き時は画像全体を水平反転して表示します（向き違いの別画像は不要です）。
  - 反転表示時のアンカー x は `画像幅 − dx` に自動補正されます（Java 版 `ImagePairs.getImage(right)` の右画像アンカー計算相当）。
  - よって `dx` は素の（左向き）画像基準で 1 回だけ書けばよく、中央（例: 64/128）なら反転してもずれません。
- `actions.xml` に反転用の別画像参照はありません（同梱資産 XML で flip 系の記述は 0 件）。Java 版 `ImagePairs` が内部で生成する右向き画像（反転画像）相当の処理は描画時の反転で行っており、**右向き用の別ファイル指定は Phase 1 非対応** です。
- マスコットの向きは実行時に決まります（起動直後は乱数・移動系は移動目標や速度の符号）。画像側での向き分けは不要です。

## 5. settings.toml での scale

`conf/settings.toml` でセット単位の拡大率（scale）を指定できます。ファイルが無ければ既定値（すべて等倍）で動き、Allowed Behaviours のトグルを操作すると自動保存されます。

書式（下の 2 形式は等価で、どちらでも読み込めます）:

```toml
[imagesets]
scale = { Shimeji = 2.0 }
```

```toml
[imagesets.scale]
Shimeji = 2.0
```

- キーはセット名（= `img/` 直下のフォルダ名）、値は倍率（数値）です。`1.0`（および未指定のセット）は等倍です。
- scale の効果は 2 箇所です:
  1. **画像**: ロード時に全フレームを `round(寸法 × scale)` へ Lanczos3 で一括拡縮します（プリスケール）。
  2. **アンカー dx/dy と速度**: アクション構築時に `round(値 × scale)` で変換します（速度は非ゼロ成分が 0 に丸まった場合、符号付き ±1 に補正されます）。
- **注意（Phase 1 の既定セット制限）**: アンカー/速度の構築時 scale には「既定セット（辞書順先頭）の scale 値」1 種のみが使われ、全セット共通で適用されます。画像のプリスケールはセット毎の scale で行われるため、セット毎に異なる scale を混在させると足元位置の整合が取れません。単一セット運用、または全セットに同一の scale を指定する場合は問題ありません。
- scale を変更した場合、画像側は Reload でも再適用されますが、アンカー/速度側は起動時に確定するため **再起動での反映が確実** です。
- `settings.toml` 全体は `[general]` / `[allowed]` / `[disabled_behaviors]` / `[imagesets]` / `[interactive_windows]` の 5 セクションで、欠落セクション・フィールドは既定補完、未知キーは読み込み時に無視されます（保存時に失われます）。トグル操作時の自動保存は、構造体フィールド順 + セット名辞書順で決定的な内容に上書きされます（説明コメントは保存のたびに付き直すため失われません）。
- 各セクション・キーの意味は、同梱の `settings.toml`（リポジトリでは `conf/settings.default.toml`。初回起動時の生成物と同一内容）にコメントで書かれています。

参考（scale だけを書く最小例）:

```toml
[imagesets.scale]
Shimeji = 2.0
```

## 6. 起動時整合検証

起動時に `conf/` `img/` は次の順で検証されます。各失敗時の挙動も併記します。

1. `conf/` `img/` の存在（exe 隣）→ 無ければ欠落パス入りのエラーで終了（例: `conf ディレクトリが見つかりません: <パス>`）。
2. `settings.toml` → 無ければ既定値。読み込み・パース失敗はファイルパス付きエラーで終了。
3. `actions.xml` / `behaviors.xml` のパース → 破損・記法不正は「ファイル:行番号: 理由」付きで終了。
4. 必須 4 種 Behavior（`ChaseMouse` / `Fall` / `Dragged` / `Thrown`）→ 欠落はエラーで終了（例: `(behaviors): 0: 必須 Behavior が欠落しています: Fall`）。
5. セット毎に画像ロード → **1 セットの失敗は warn ログ + スキップ**（他のセットは続行。例: `画像セット 'X' の読み込みに失敗したためスキップします: ...`）。
   - デコード不能な PNG → PNG ヘッダから寸法が読める場合、同寸法の全透明フレームで代替 + warn。
   - PNG ヘッダも読めないファイル → そのフレームを欠落扱い + warn。
   - サイズ混在 → 警告 1 件で続行（各フレームは自身の寸法を保持）。
6. セット毎に conf↔set 参照検査（`actions.xml` の全アニメーションの `Pose` 参照がセット内 PNG に存在するか）→ 欠落があれば **そのアニメーションを丸ごと無効化** します。ログ形式は `アクション '<名前>' のアニメーション #<番号>: 画像 <ファイル名> が見つからないため無効化しました`（ファイル名はカン区切りで複数列挙）。
   - 無効化の実適用（構築時の定義除去）は **既定セット分のみ** です。非既定セットでだけ欠けている参照は除去されず、描画時に warn（同一内容は連続抑止）で描画スキップになります（§8）。
7. 有効なセットが 1 つも無い → 「有効な画像セットが 1 つもありません: …配下に画像 set（PNG のフォルダ）が必要です」で終了。

なお起動は単一起動制限ありです（既に起動している場合は「既に起動しています（単一起動のため終了します）」で終了）。ログは標準エラー出力に出ます（既定レベル info・`RUST_LOG` 環境変数で変更可）。コンソールから起動すると確認しやすくなります。

## 7. Reload（実行中差し替え）

トレイメニューの **Reload** を選ぶと、`conf/` と `img/` を再読み込みします。

**反映されるもの:**

- 画像（ImageSet 全体。`settings.toml` の scale による画像プリスケールも再適用されます）
- `behaviors.xml` の行動表

**反映されないもの（Phase 1）:**

- `actions.xml` の変更（アクション構築に使う定義は起動時に確定するため）
- `conf/settings.toml` の変更（settings は起動時に読み込んだ内容のまま）
- トレイ「呼ぶ」サブメニュー・マスコット右クリック popup のセット一覧（起動時に構築）

**成功時の挙動:**

- 全マスコットは位置（anchor）・向き・一時停止・ドラッグ状態を **維持したまま** 新しい画像/行動表へ付け替わります。実行中の動作の進行はリセットされ、現在の行動が新しい行動表に存在して有効なら同名で再構築、そうでなければ次の行動を再選択します。
- Reload 後に `img/` から無くなったセットのマスコットは、既定セット（辞書順先頭）へ付け替わります。
- 全ウィンドウが強制再描画されます。

**失敗時の挙動:**

- XML 破損・必須 Behavior 欠落・`img` 列挙失敗などは「Reload に失敗したため現状を維持します」のエラーログとともに **現状維持**（何も変わらない）になります。
- 全セットの画像ロードに失敗した（= 有効セット 0 件）場合はエラーにはならず、全マスコットが消去されます（削除は次 tick で反映・アプリは起動したまま）。

**新セットを追加したときの注意:**

- Reload で新しいセットの画像はロード・登録されますが、「呼ぶ」メニューには新セットの項目は現れません（**再起動すると現れます**）。
- Reload で削除したセット名のメニュー項目を押しても、未知セットとして spawn はスキップされるため何も起こりません。

## 8. 制限（Phase 1）

1. **実行中のファイルウォッチ差し替えなし**: 画像ファイルの上書きやフォルダ追加は自動検出されません。トレイ Reload（または再起動）で反映してください。
2. **セット固有の定義**: `actions.xml` / `behaviors.xml` は既定で `conf/` 直下の 1 つが全セット共通で使われます。セット固有に変えたい場合は `img/<Set>/conf/` または `conf/<Set>/` に置いてください（探索順は §2）。
3. **Settings GUI なし**: 設定画面はありません（トレイメニューと `conf/settings.toml` のみ。UI 文言と Behavior 名の翻訳は §10）。
4. **効果音**: 使い方と制限は §11（同時に鳴るのは 1 音のみ・`Volume` は反映されません）。

## 9. トラブルシューティング

**Q: 画像が白い（背景の四角が見える）**
A: 透過なし PNG（背景が不透明）です。α チャネル付き PNG で保存し直してください。

**Q: 足元の位置がずれる**
A: `ImageAnchor` の誤差です。画像左上原点・(x=中心, y=下端) が基本（128×128 画像なら `64,128`）。scale 指定時はアンカーも同じ倍率で拡縮されるため、倍率を変えた後に位置がおかしい場合は画像・アンカー・scale の整合を確認してください。

**Q: 「conf ディレクトリが見つかりません」で起動しない**
A: exe と同じ場所に `conf/` `img/` がありません。エラーに表示されたパスの位置に配置してください（`cargo run` 実行時は `target/<profile>/` 配下がその場所）。

**Q: 「…: XML として解釈できません」等の行番号付きエラーで起動しない**
A: `actions.xml` / `behaviors.xml` の破損です。表示された行番号付近を修正してください。

**Q: 「必須 Behavior が欠落しています」で起動しない**
A: `behaviors.xml` から `ChaseMouse` / `Fall` / `Dragged` / `Thrown` のいずれかが消えています。

**Q: 「有効な画像セットが 1 つもありません」で起動しない**
A: `img/` 直下にセットフォルダが無いか、全セットの画像ロードに失敗しています。ログの warn を確認してください。

**Q: トレイの「呼ぶ」にセットが出ない**
A: セットは「`img/` 直下のディレクトリ」だけが対象です（`img/` 自体や `img/XXX/YYY/` は不可）。メニューは起動時に構築されるため、実行中に追加したセットは Reload でも現れず、再起動で現れます。

**Q: 特定の動きだけしない／動きの途中で固まって見える**
A: そのアニメーションが参照する画像がセットに無く無効化されている可能性があります。ログに「…が見つからないため無効化しました」が出ていないか確認してください。

**Q: マスコットをクリックできない／掴めない**
A: クリックした場所が α=0（完全透明）領域です。画像の不透明部分をクリックしてください。

**Q: 編集したのに反映されない**
A: 反映タイミングは対象によります。画像 / `behaviors.xml` = トレイ Reload（または再起動）、`actions.xml`（`Sound` 属性の追記など）/ `settings.toml` / 言語辞書（`conf/lang/`）= 再起動。効果音の WAV ファイル自体は再生時に解決されるため、置くだけ（または差し替えるだけ）で次の再生から反映されます。

**Q: 二重起動できない**
A: 単一起動制限（ユーザーセッション内で 1 プロセス）です。「既に起動しています」で終了します。

## 10. 表示名の翻訳（言語辞書）

トレイ／マスコット右クリックのラベルと、右クリック「個別行動指定」に並ぶ **Behavior 名** は
言語辞書で翻訳できます。

- **置き場所は `<conf>/lang/<code>.toml` に 1 つだけ**（例: `conf/lang/ja.toml`）。画像セット毎の
  `conf/<Set>/` や `img/<Set>/conf/` は `actions.xml` / `behaviors.xml` 専用で、辞書は読まれません。
- 言語の選択は `conf/settings.toml` の `[general] language`（同梱: `"en"`（既定）/ `"ja"`）。
- 書式は **フラットな TOML**（`キー = "訳"`）。`[セクション]` は使えません。キーは次の 2 種です:
  - UI ラベル（例 `CallShimeji = "しめじを呼ぶ"`。Java 版の `language.properties` と同じキー名）
  - **Behavior 名をそのまま**（例 `ChaseMouse = "マウスを追っかける"`）
- 辞書は全セット共通の 1 ファイルです（同じ Behavior 名はどのセットでも同じ訳になります）。
- **変更の反映は再起動**です（辞書と `settings.toml` は起動時に 1 回読み込み。トレイの Reload は
  辞書・設定を読み直しません）。
- 辞書に無いキーは元の文字列のまま表示され、ログに警告が 1 回出ます（キーごと）。
- 訳例は同梱の `conf/lang/ja.toml` を参照してください（Behavior 名の訳も入っています）。

> 補足: Java 版は未訳の Behavior 名を `Sit And Face Mouse` のように単語区切りへ整形して表示しますが、
> 本実装は元の名前（`SitAndFaceMouse`）のまま表示します。

## 11. 効果音（`<Pose>` の `Sound` / `Volume`）

`<Pose>` に `Sound`（ファイル名）を書くと、そのポーズが適用されたときに鳴ります。

- **置き場所**: 次の順に探します（最初に見つかったものを使用）。
  `img/<Set>/sound/<file>` → `sound/<Set>/<file>` → `sound/<file>`
  （`sound/` は exe と同じ場所。ファイルは**再生時に解決されるため、WAV を置くだけで次の再生から鳴ります**＝再起動不要）
- **書式の例**:

  ```xml
  <Pose Image="/shime1.png" ImageAnchor="64,128" Velocity="-2,0" Duration="6" Sound="se.wav" Volume="1.0"/>
  ```

- **鳴らしたいポーズにだけ**書いてください。ポーズが適用されたフレームで音がセットされ、その音が鳴り終わっていれば鳴り直します（歩行の足音なら 1 ループ中 1 ポーズに書くのが定石）。**全ポーズに書くと途切れず鳴り続けます。**
- 形式は Windows `PlaySound` が扱えるもの（WAV など）です。
- 制限:
  - 同時に鳴るのは **1 音のみ**。別の音を鳴らすと前の音は止まります。
  - `Volume` の値は **反映されません**（音量 API が無いため。書いてもエラーにはなりません）。
  - ファイルが見つからない場合はログに警告が出て無音で続行します（起動は止まりません）。
- 停止: `Mute` アクション（`Sound` 属性でその音だけ / 省略で全停止）。
- 有効/無効: トレイの Allowed Behaviours →「効果音」（`conf/settings.toml` の `[allowed] sounds`）。
